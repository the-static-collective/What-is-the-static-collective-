# The Front Room

> **Orientation is not retrieval.**
>
> This is an orientation space for an assistant entering or re-entering the Static Collective's work. It exists to keep the thread proper across conversations, tools, projects, and discontinuities. It is **not** a human-facing welcome page, product pitch, substitute project index, or canonical description of every repository.
>
> **The present request selects the door.** The room must not select the request.

The room is a stable landmark, not a snapshot of the entire Collective. It may expose nearby fields, relevant boundaries, useful entrances, and unresolved fog. Enter briefly. Leave freely. Do not impose its vocabulary on unrelated tasks.

## Entry protocol

1. **Receive the present particular.** Identify what the user is actually asking, including named projects, constraints, and corrections. Do not replace it with a general Collective narrative.
2. **Orient at field scale.** Identify only the nearby areas and unresolved questions that might matter. Scanning a door's label is not traversing its contents.
3. **Choose a bounded crossing.** Follow an indicated door only if it helps with this request. Prefer project-owned sources, executable artifacts, current records, and explicit human corrections over summaries here.
4. **Preserve distinctions.** Observation, inference, proposal, implementation, receipt, and authority remain separate. Shared names and themes do not merge projects.
5. **Keep fog visible.** If current descriptions conflict, name the contradiction; do not silently resolve it into a coherent story.
6. **Carry the useful trace.** Retain the source, why it mattered, what changed, and what remains open. Stop traversing when the task is adequately grounded.

```text
present request
    ↓
orient: nearby fields + known uncertainty
    ↓
select relevant door(s)
    ↓
inspect owning source and current evidence
    ↓
perform bounded work
    ↓
leave a reconstructible trace
```

## Project-identity correction — inspect the owning code

**Source-backed reconciliation, 2026-10-13:** WITNESS **is** a community audio Bible project. The [main README](https://github.com/the-static-collective/WITNESS/blob/main/README.md) says so; its [unmerged Genesis branch](https://github.com/the-static-collective/WITNESS/tree/genesis/community-audio-bible-001) contains an actual Matthew 5 recording prototype and Supabase shared-room contracts. A prior orientation edit had incorrectly treated WITNESS as unrelated to Scripture. That classification is superseded by the inspected project sources.

Keep the three Scripture organs distinct:

- **[WITNESS](https://github.com/the-static-collective/WITNESS)** — human audio readings anchored to Scripture passages, local-first receipts, and optional community assembly. The current prototype assigns alternate verses for a two-voice test; [CANON-001 — FREE WITNESS](https://github.com/the-static-collective/WITNESS/blob/genesis/community-audio-bible-001/docs/CANON-001-FREE-WITNESS.md) explicitly says unrestricted voluntary reading, not verse assignment, is the intended contribution model.
- **[Revival](https://github.com/the-static-collective/revival)** — source-backed Bible kernels, textual/linguistic witnesses, translation choices, and attributable projections.
- **[Upper Room](https://github.com/the-static-collective/Upper-room)** — shared Scripture attention, room encounters, branching and voluntary re-entry.

**Maturity boundary:** WITNESS's main branch is README-only; the recorder, schema, and shared-room code remain in an open pull request. Source code and deployment configuration do not themselves prove a successful two-phone field trial or a deployed service.

The capitalized `WITNESS` project is also distinct from this documentation repository's lower-case `witness/` continuity notebook. Names resemble each other; purposes differ.

## Authority / status boundaries

```text
human correction ≠ silent project rewrite
orientation      ≠ retrieval
directory label  ≠ project identity
public           ≠ canonical
branch exists    ≠ branch accepted
proposal         ≠ implementation
implementation   ≠ field proof
witness          ≠ authority
representation   ≠ occurrence
compatibility    ≠ permission
absence          ≠ nonexistence
```

The current human request governs intent and corrections; project-owned artifacts, tests, receipts, and source witnesses govern factual claims about implementation. When these disagree, report the disagreement and investigate rather than laundering one into the other. This room never outranks either.

## Frontier cues, not mandatory itineraries

- **Continuity across discontinuity:** how to re-enter prior work without claiming a memory, identity, or source that was not actually carried. [The Room Can Vanish; the World Remains](patterns/world-reentry-memory/).
- **Local authority after crossing:** what survives transformation, how receipts remain inspectable, and who owns RECEIVE, HOLD, refusal, and disposition. Start in the relevant project's contracts, not with this overview.
- **Human return loop:** the proposed/partially proved path from a particular need through review, Campfire, confirmation, and possible Book of Acts handoff; never infer full deployment from a public seam.
- **Unplaced or unresolved work:** [unresolved questions](witness/unresolved.md), [primitive incubator](frontier/primitive-incubator/), and [public Git inventory](atlas/generated/README.md). Keep the difference between a preserved question and a verified result.

Do not present these cues as the only active work or a ranked priority list.

## Room failure conditions

The room is failing when it becomes a visitor brochure; routes every conversation into Collective concerns; loads a standard large context dump; treats neighboring projects as one product; promotes summaries over current source; quietly resolves contradiction; labels a project from name-association; or expands into a second database.

**If it fails, make the room smaller and the doorway more exact.**

> **Starting place, not source of truth. Doorway, not destination.**
