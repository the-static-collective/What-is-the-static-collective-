# Source ledger · What was actually looked at

## Evidentiary tiers

| Tier | Meaning | Safe claim |
| --- | --- | --- |
| O · observed | Repository/branch/PR objects returned by GitHub, or the dated generated public Git map | A pointer, title, state, parent branch or artifact reference was visible when inspected |
| D · documented | A PR body, README, design or authored witness says a behavior exists | The source **claims** that behavior, not that an independent test passed |
| V · verified | An independently run test or checked field artifact with receipt | Only the exact proof performed, under its limits |
| I · inferred | An explicitly labeled relationship synthesized from multiple sources | Possible pattern or useful question, not established integration |
| P · proposed | A roadmap, branch, experiment, offer or design | Not adopted, deployed, authorized or accepted |
| A · admitted | Explicit project-/human-owner disposition for that exact scope | Never inferred from a branch, PR, merge, generated doc or this wiki |

## Known conflicts and fog

- The publicly refreshed Git map covers **all public refs**, while this first editorial pass deeply reads **selected PR descriptions only**. Do **not** call it a source-code or test audit of all repos.
- CANNON #29 describes its own **102 candidate-repository census**, with **26 pinned README blob observations and 76 unassessed**. That candidate census has a different observation method and scope from the **86-public-repo** GitBook atlas. Neither number should silently replace the other.
- The source repository's [Current Executable Project State](https://the-static-collective.gitbook.io/the-static-collective-docs/project-state/project-state) is dated **2026-08-22**; it cannot establish current October executability without owner-source checks.
- Open PRs are not merged. Stacked PRs depend on ancestor branches; comparing a child only with main can fabricate an integration story.
- Statements like 'verified' in a PR body are **author-supplied reports** until a separate check reproduces them. The present workspace did not execute project test suites.
- Whether any partner organization accepted field deployment, which exact creative or legal rights exist, and whether any hardware trial happened remain **outside the presently verified evidence**.

## Repair procedure

1. Discover the source-owner repo and exact branch/commit SHA.
2. Read branch artifacts, tests and receipts, not just the README.
3. Record PR head/base and exact tested state; inspect whether a PR later merged, closed, changed or was superseded.
4. Write an **observed / documented / verified / inferred / proposed / admitted** label.
5. On disagreement, preserve both time-stamped claims; ask owning source, not the atlas, for disposition.
6. Update the generated index through its **existing collector**; edit the semantic layer by an independently reviewed PR.

This page is a provenance receipt, not a claim of broad independent certification.
