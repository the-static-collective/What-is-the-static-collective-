# STATIC SEED · Work & Storyship — v0.2

The **House of Houses** is a portable method and small local-first registry for growing one person's independent ecosystem of projects. It is inspired by fellowSHIP's independent rooms, STATIC-OS's habitat boundary, and Static Workbench's human-operated desk, but does **not** install those independent projects.

```text
OWNER'S HOUSE
 ├─ HOME: Cleaning business
 │   ├─ ROOM: Customer operations
 │   └─ ROOM: Training and service improvements
 ├─ HOME: Story world
 │   ├─ ROOM: Canon and continuity
 │   └─ ROOM: Novel one
 └─ HOME: Publishing
     └─ ROOM: First release

       ↓  attach only relevant workbenches
 BUSINESS DESK · MEMENTO · MOTIF · STORYSHIP · lemonPRESS · LOADOUT · BRIDGE
```

**House:** a person's independently owned ecosystem. **Home:** a project domain with its own records and decision gate. **Room:** a bounded purpose within a home, optionally collaborative in a future authorized host. **Workbench:** an attachable method; visibility and execution permissions do not follow an attachment. **Crossing packet:** an owner-reviewed proposal to share selected references, not the source records or access.

## Start here

1. Open `START-HERE.md` or invoke the `start-here` skill and say **"Show me my house."**
2. Use `housekeeper` to propose or organize homes; `room-maker` to organize rooms; `workbench` to attach reusable methods.
3. For a no-plugin path, copy `portable-starter-prompt.txt` into a fresh ChatGPT conversation.
4. For durable local records, use the optional standard-library `toolkit/seed_house.py` CLI (instructions in `docs/LOCAL-REGISTRY.md`) or save an owner-reviewed JSON registry yourself. A ChatGPT response is not persistent storage.
5. Read `docs/HOUSE-OF-HOUSES.md` for ownership, consent, and growth rules; try `examples/friend-house.example.json` with entirely fictional data.

## Independent skill doors

`start-here`, `housekeeper`, `room-maker`, `workbench`, `business-desk`, `storyship`, `lemonpress`, `memento`, `motif-lab`, `loadout`, `bridge`.

**Status:** Eleven packaged instruction skills, JSON examples, and an optional local Python registry tool; **no hosted homes, user accounts, external integrations, live shared-room service, database connection, scheduled tasks, or automatic Git sync**. A future web/MCP implementation is a distinct integration requiring user permissions, data handling, testing, and hosting.

This package carries **methods**. It carries no owner's private archives, customers, manuscripts, OAuth credentials, or claimed right to modify other systems.
