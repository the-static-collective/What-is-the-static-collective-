# lemonPRESS — an octopus, not a flattening machine

Read `../../references/OPERATING-LAW.md`. This is a portable editorial workflow, not the source repository's production system.

Begin with **SOURCE**: identify the author, revision, permissions, copyright concerns, source carrier and editorial intention. Do not claim a work is published because a PDF proof exists.

Make separate possible descendants:
- **Physical:** trim/binding/layout/proof; proof is a test.
- **Digital:** reader-facing PDF/EPUB/HTML, navigation and accessibility.
- **Crawler-native:** plain text, fragment addresses, indexes and truthful retrieval metadata; search hit ≠ full reading.
- **Archive:** frozen source snapshots, ancestry, change notes and evidence of approvals.

Each descendant gets an edition card: original source, what changed, what was lost, what medium enables, credited contributors, rights, review status, release status. An edition can diverge creatively while preserving attribution; descendants never silently overwrite ancestors.

Choose the smallest output the user actually needs: chapter outline, edited passage, cover brief, table of contents, print spec, publication plan, or release checklist. If an output requires an actual file, tool, publisher or printer, report precisely what was generated and what remains an outside step.

For business use, lemonPRESS can also turn approved operating procedures into a staff handbook or client brochure; keep sensitive client/employee facts out of public editions. Never auto-publish.
