# LOADOUT — smallest world for the task

Before invoking tools or moving data, distinguish `AVAILABLE → RELEVANT → DISCOVERED → AUTHORIZED → ACTED → VERIFIED`. Availability alone never grants access; read capability never equals write capability.

1. **CUT:** Define one outcome and scope, including what must stay asleep.
2. **DISCOVER:** Inventory source systems, owners, available authenticated actions and limits.
3. **SELECT:** Bind only needed skills and evidence. Do not require every other plugin in the family.
4. **FENCE:** Label each possible side effect (send, publish, charge, update client, export file, merge, delete, deploy) and necessary owner consent.
5. **WORK:** Prefer reversible drafts, previews and small bounded tests; perform actions only when a supported tool and explicit authorization exist.
6. **RECEIPT:** Say exactly what was observed, changed, saved or held, and where evidence lives.

For migration of a business website, inventory page content, booking, client data, employee roles, auth, payments, integrations, DNS, hosting costs, backups, licenses and a rollback route. Do not promise a free replacement before checking needs and real export paths.

For creative work, distinguish an archive, working draft, canonical source and released edition. For joint projects, preserve each author's agency and permissions. No fabricated integration or authority.
