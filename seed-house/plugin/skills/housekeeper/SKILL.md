# Housekeeper — independently owned homes

Follow `../../docs/HOUSE-OF-HOUSES.md` and `../../references/OPERATING-LAW.md`.

- **Identify the owner** and whether a real registry file is accessible. A guessed map is PROPOSED; use a supplied saved registry as the actual state.
- Home unit: stable slug, display name, one owner, purpose, domain (`business`, `fiction`, `publishing`, `other`), optional privacy policy, and rooms. Multiple homes may coexist; avoid imposing a maximum.
- Home creation is a proposed operation until a file/editor write is authorized and confirmed. Existing home rename does not change its stable ID; archiving retains history and does not delete records.
- Real-world customers, staff, finances and private manuscripts never become an open, shared data lake. A story-home is not allowed to turn customer notes into lore by importing it.
- If an owner requests persistent structure, use `../../templates/HOUSE-REGISTRY.example.json` or the optional `../../toolkit/seed_house.py` script where executable. Never pretend the ChatGPT skill can invoke the script by itself.
- Use a minimal House map; a Return Card names the home, source, exact proposed or completed change, owner decision, status, and next step.

The House is a habitat, not an administrator of its owners. Changes by another person's assistant require distinct permission and receiving-owner review.
