# Native Color Witness / Chromatic Decompression

Haunted Toaster has reached a point where color no longer needs to mean only **a palette imposed on an image**.

The source image has its own chromatic testimony.

> **The photo is a witness, not just fuel.**

A second compositional law follows:

> **Stylization may compress the source, but it should sometimes decompress and let the source testify again.**

This note records the design field. **Implementation authority lives in Haunted Toaster GitHub issue** [**#115**](https://github.com/the-static-collective/the-haunted-toaster/issues/115)**.** Current renderer evidence and project-owned code outrank this notebook page.

## Why this appeared now

The renderer already has deterministic section-relative Color Drift and Possession Arc composition. The Gold Star field run showed that substantial chromatic and structural development can emerge without spending ordinary mutation entropy constantly.

That makes a new question visible:

> What if the Toaster does not merely move _through its own palette_, but forms a relationship to the native color field of the photograph itself?

## Native Color Witness

The source should have lawful opportunities to re-enter the rendered world in its own chromatic language.

Possible forms include:

* whole-frame decompression windows;
* partial native-color bleed;
* local witness zones;
* later, semantically important regions that resist total recoloring.

The first implementation does not need semantic segmentation. A bounded global/windowed proof is enough to establish the law.

The important distinction is that **native-color return is an event**, not a permanent obligation to preserve realism.

## Chromatic Relationship Engine

Palette can be relational rather than merely imposed.

A source-native chromatic profile could support relationships such as:

* **preserve / echo** — remain near the source field;
* **analogous / overlap** — extend neighboring hues;
* **complementary** — oppose dominant source hues;
* **split / offset** — move away under bounded control;
* **clash / tension** — introduce chromatic friction deliberately;
* **bleach / drain / residue** — descend into reduced-color states;
* **return / reveal** — restore source chroma after distance.

Working ontology:

> **Palette is not only imposed. It can be relational.**

This does not weaken garment law, Toast Feel, Color Drift, or Possession Arc. It gives those systems a new witness to relate to.

## Color as frequency

A useful deeper model is to treat color behavior as a kind of compositional frequency field rather than a bag of swatches.

```
hue drift       -> modulation / directional movement
saturation      -> chromatic pressure / intensity
luminance       -> exposure / weight
chromatic clash -> tension
native return   -> release / resolution
```

In this model the photograph contributes a **native chromatic spectrum**. The Toaster may then resonate with it, harmonize with it, counterpoint it, distort it, suppress it, or reveal it again.

The metaphor is useful only if the implementation remains measurable, deterministic, and receipt-bound.

## Composition law

A likely ordering is:

```
source image
  -> NativeChromaticProfile
  -> source-relative chromatic relationship
  -> section-relative Color Drift
  -> optional decompression / native-color return
  -> shared preview + production compiler
```

The exact order must become explicit project law before implementation. Source-relative palette logic and energy-relative drift should compose, not silently fight.

## Relationship to visual phrasing

Native-color reveal is especially valuable because it can behave like musical phrasing:

```
withhold
  -> accumulate distance
  -> open / reveal
  -> residue
  -> re-enter treatment
```

The reveal may function as preparation, strike, release, or aftermath. This connects directly to the broader rule that **cool is an event**: if original color is visible all the time, it loses its phrasing power.

## Relationship to recurrence

A returning section does not have to reset to the same palette state.

It may return as a descendant:

```
first chorus
  -> source color held at distance

second chorus
  -> partial source-color memory

final chorus
  -> native-color reveal / transformed return
```

This gives recurrence ancestry and consequence without requiring a scene-cut mentality.

## Guardrails

* native color should not always dominate;
* reveal should remain compositional rather than accidental;
* source color may re-enter partially, locally, temporarily, or sectionally;
* palette coherence must survive the return;
* both chromatic harmony and chromatic tension remain legal;
* no renderer-local image analysis;
* no ambient randomness;
* no preview-only color semantics;
* legacy replay meaning remains pinned under its renderer policy;
* semantic segmentation is not a prerequisite for the first proof.

## Release boundary

This is a deeper compositional slice, not an instruction to destabilize the current package candidate.

Near-term line remains the known-good renderer, Listener integration/parity work, Toast Feel work, and package proof. Native Color Witness belongs behind that line until the current package is secure.

## Residual fog

Several questions remain intentionally unresolved:

* Which native chromatic statistics are sufficient for v1?
* Should source-relative relationship be a score property, a derived plan, or renderer-profile policy?
* At what boundaries should decompression windows be eligible?
* How should Color Drift modulate a source-relative baseline without erasing its identity?
* When does local semantic color preservation become worth the added analysis complexity?

Those questions belong to implementation evidence, not notebook neatness.

***

> **Let the image travel far enough to become strange, but keep a lawful road by which its own color can return.**
