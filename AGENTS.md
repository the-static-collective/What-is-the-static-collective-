# The Static Collective — ONE GARDEN entry

This is an AI-to-AI *working* doorway, not a public relations document. **All ongoing work is one sprawling garden.** Repositories are individually owned organs and experiments, not separate product worlds.

## Required re-entry
1. The current human request chooses the relevant project(s). Use GitBook Front Room only for orientation, then follow current project-owned files and exact commits, PRs, tests and correction receipts.
2. **One bounded conversation-history pass before substantive project building in fresh chats.** Search the relevant past ChatGPT conversations by project name, aliases, adjacent experiments, foundation decisions, explicit user corrections, former failures and recent activity. This is a dual habit: the assistant initiates it rather than making the human reconstruct the past. Search only what's relevant; reconcile chat leads against current owner code/PRs/tests. If past chats are unavailable, mark `HISTORY_COVERAGE_BOUNDED` and proceed with available evidence. Do not mistake a chat summary for project canon.
3. **Private repositories count.** Discover every accessible private and public repository when the task requires it. Do not substitute the public Living Git Map for authenticated discovery. If access is incomplete, say so explicitly. Do not publish private names, files, or credentials merely because a public index exists.
4. Prefer each project's AGENTS.md, CONTINUE.md, existing status contract, and human-approved foundation/intent record. README may be old, autogenerated, archival or absent; it is never the default authority for changing operational status.
5. Preserve the difference between intent, hypothesis, draft PR, merged code, deployed runtime, actual field test and user correction. A model's summary is not a source; use GitHub, Drive and project-owned original artifacts.
6. Treat MEMENTO as the historical return lane, MOTIF as the proof/reasoning lane, GHoT as the unit-of-work lane, and the maps/GitBook as navigation. Do not create a new central canon or silently promote retrieved associations.
7. On consequential work, leave a small source-linked receipt in the local owner organ. Do not force the human to re-explain foundations that are already preserved.

## Source-driven pulse
The first implemented, narrowly-scoped generator is at https://github.com/the-static-collective/GHoT/tree/main/garden . It can discover all repositories visible to its authenticated token (including private) and generate a CONTINUE.md view from source-owned intent and GitHub changes. Its public, repo-scoped scheduled workflow does not have secret cross-repo access. Never infer universal automatic synchronization from its existence.

Status: continuity retrieval across genuinely fresh chats remains to be tested. An instruction file is a discovery aid, not proof every future model read it.

## ChatGPT project-wide entry
For the full fresh-chat working protocol, see [GHoT Garden Router 001](https://github.com/the-static-collective/GHoT/pull/140) and the source-owned `chatgpt/ENTRY.md` file in GHoT. ChatGPT Project/Custom Instructions must be installed in the ChatGPT product; a GitHub file is not automatically injected into all chats. Use **Default** project memory when essential historical chats live outside the Project; project-only memory excludes them. The entry run is one focused history search followed by evidence reconciliation, not a full-garden preload.
