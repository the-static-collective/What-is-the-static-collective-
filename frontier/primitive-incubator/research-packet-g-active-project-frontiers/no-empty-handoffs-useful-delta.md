# No Empty Handoffs — Useful Delta

**Maturity: PROJECT-BACKED / CROSS-PROJECT CANDIDATE.** Do not silently promote to Collective law or grant authority to unrelated repositories.

## Failure that selected the question

A real phone user asked First Circle for **advice on fixing something**. The system generated a card whose suggested next step was **make a simple invitation**. That created a self-referential bureaucratic loop: a card about making the next card, with no useful diagnostic work performed. The page loaded and the card contract passed; **the original need was no closer to resolution**.

## Candidate law

> **Do the work the system can actually do. Never return a task to create the artifact the system could already have created. Report the precise remaining obstacle rather than silently exporting labor.**

The constraint is purpose-relative. If a person requests an invitation, a fully written, usable invitation is work. If the person requests a repair diagnosis, that same invitation is a mismatched substitute.

**Prepared work is not world completion.** A recipe does not cook a meal, a draft does not send a message, a safety check does not repair a machine, a passing test does not prove human benefit, and a signed receipt does not certify truth.

## Observable exits

| Outcome                  | Evidence required                                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| Prepared locally         | An actual answer, diagnostic procedure, complete script, runnable test, recipe, ready draft, or playable rules are present now. |
| Partial with blocker     | Something genuinely usable exists; the remaining requirement, responsible party, and uncertainty are explicit.                  |
| Waiting on owner         | An external action needs consent, access or a destination-owned result. Do not claim it happened.                               |
| Empty handoff            | Only a promise, invitation to make an invitation, ticket to make a ticket, or repeated goal-diverting instruction exists.       |
| Verified external result | Only the owning destination may warrant this, under its own evidence and authority rules.                                       |

## Project-owned specimens

* [webZ First Circle 002 — actual prepared work, not an empty next-step card](https://github.com/the-static-collective/webZ/pull/242) — task-specific repair triage, pantry recipe, volunteer message, offer and playable rules; `BOUNDED_GUIDE`, `READY_TO_USE_DRAFT` and `UNRESOLVED` remain distinct.
* [webZ First Circle return & Jubilee field kits](https://github.com/the-static-collective/webZ/pull/244) — a self-reported unsuccessful return can trigger another ready local step; Jubilee role selections produce actual run sheets, recipe, sound preflight, facilitation and lesson scripts.
* [webZ Jubilee → First Circle portable crossing](https://github.com/the-static-collective/webZ/pull/245) — a visitor explicitly exports the complete ready kit as a First Circle card and can import it, report a result and preserve the artifact, without remote submission or inferred verification.
* [JAR;VIS Useful Delta 001](https://github.com/the-static-collective/JAR-VIS/pull/48) — opt-in structural rejection of empty handoffs.
* [JAR;VIS Progress Gate 002](https://github.com/the-static-collective/JAR-VIS/pull/49) — explicit requested-task type versus produced-artifact type, bounded local JSON CLI, blocked external-outcome claims and recursive repeat checks.

All are distinct owning sources. Their tests show bounded implementation and regressions; **no independent field study yet establishes that a visitor's original practical problem was solved**.

## The first-inch test

Ask a person who has just used the interface: **"What usable thing do you now have that you did not have when you arrived?"** Keep separately the evidence for what the code prepared, what the human did, what the external recipient confirmed, and what remains unresolved.

A candidate graduates only after materially different real-world tasks show actual utility, the failed specimens remain inspectable, and each relevant organ independently chooses to adopt it.

**No authority from adjacency. No success from a generated card. No recursion that only creates more administration.**
