# RECURRENCE-INDEPENDENCE-001 — Count Births, Not Echoes

**Status:** candidate cross-project crucible · 2026-08-26

**Bears on:** Reticulate Continuity / creative lineage / Haunted Toaster / Daily Slice / ALEX dependency families

> **Recurrence is an observation. Independent invention is an ancestry claim.**

The Collective intentionally produces large families of related artifacts. Raw repetition can therefore manufacture the appearance of independent recurrence unless the visible instances are partitioned by attributable dependency.

## Input set

Choose one recurring relation or motif with enough appearances to tempt overclaiming.

Example shape:

```text
A1 A2 A3 A4 A5 A6 A7 A8
```

Record the raw recurrence count first. Do not clean it away after ancestry analysis.

Then attempt the smallest justified partition:

```text
DIRECT DESCENT
INDIRECT DESCENT
SHARED DECLARED PRESSURE
INDEPENDENT WITHIN DECLARED SCOPE
UNKNOWN CONNECTION
```

Do not convert shared pressure into genealogy merely because both outputs were influenced by the same weather, corpus, cultural field, model family, human taste, or design constraint.

## Minimum specimen

A useful hostile setup is:

```text
F1  A1 A2 A3 A4
    shared direct prompt / seed

F2  A5 A6
    separate prompts
    shared declared upstream source

A7  no known ancestry bridge
    but generated after exposure to same project vocabulary

A8  isolated enough to test as
    independent within declared scope
```

The tester must be allowed to conclude:

```text
raw recurrence count = 8
known dependency families = 2
independent births = at least 1 within declared scope
unknown = at least 1
```

It must **not** be required to manufacture one definitive independent-birth count when the ancestry graph is incomplete.

## Cut test

For every claimed independent birth, ask:

> **Which plausible carrier between these births has actually been cut or ruled out?**

Candidate carriers include:

```text
same prompt
same seed
same source artifact
same earlier output
same model context
same training/retrieval lineage when knowable
same human suggestion
same bibliography
same transformation recipe
shared direct ancestor
shared indirect ancestor
```

Unknown or inaccessible carriers remain fog. They do not become evidence of dependence, but they also do not become proof of independence.

## Remove-one pressure

Collapse each known family to one representative and ask whether the recurrence remains materially interesting.

Then remove one family at a time:

```text
SURVIVES REMOVAL
DEGRADES
COLLAPSES
CHANGES INTERPRETATION
INSUFFICIENT TO TEST
```

A pattern that goes from eight appearances to one dependency family has not failed. The correction is the result.

A pattern that continues to arise across causally separated families deserves stronger attention, not automatic metaphysical promotion.

## Required witness

Preserve:

```text
raw appearance count
family partition
basis for each family edge
scope of independence claim
unknown relations
remove-one results
which carriers were actually ruled out
```

## Failure conditions

Refuse a strong recurrence claim if the system:

- counts descendants as separate inventions;
- treats visual difference as independent ancestry;
- treats visual similarity as shared ancestry;
- converts `unknown` into `independent`;
- converts shared environmental pressure into demonstrated transmission;
- hides the original raw recurrence count after correction;
- claims absolute independence when only a bounded dependency surface was inspected.

## Connection to ALEX

ALEX may carry an executable fixture for the generic inference failure `RECURRENCE != INDEPENDENT INVENTION`. That fixture does not own creative lineage semantics here. This page owns the cross-project experimental question beside Reticulate Continuity.

## MADDCLOWN extension

The fun version is adversarial birth-separation.

Take the strongest recurring relation and deliberately generate new conditions designed to **cut known carriers**:

```text
new model
new prompt author
no shared seed
no shared example set
no access to prior outputs
different domain vocabulary
same structural question
```

If the relation still appears, record it carefully.

Then try to kill it again.

> **The interesting recurrence is not the one we can count most often. It is the one that keeps being born after the roads between the births have been cut.**
