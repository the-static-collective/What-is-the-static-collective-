# Freeport v0 — Foreign Material Without Admission

> **Status:** incubating security / membrane primitive. This is a topology for handling foreign material, not a claim that residence sanitizes or legitimizes it.

## Compression

A world needs a lawful place for something to arrive **without yet entering the world**.

```
FOREIGN / UNKNOWN
      ↓
   FREEPORT
      ↓
inspect | translate | compare | quarantine | re-export | petition
      ↓
LOCAL IMPORT GATE
      ↓
LOCAL WORLD
```

Core separation:

```
present in Freeport
!= admitted locally
!= constituted locally
!= authorized locally
```

The useful meaning of **free** is not free authority or free execution. It is freedom from **premature local constitution**.

## Why this exists

The dangerous crossing is not only malicious input.

It is any material whose foreign meaning, shape, executable character, ancestry, or claimed authority is silently accepted as local merely because it crossed a technical boundary successfully.

A strict binary gives poor choices:

```
unknown -> reject
unknown -> admit
```

Freeport creates a third lawful state:

```
unknown -> held
```

The thing may remain attributable and available for study while remaining outside local consequence.

### Executable / Resonant Membrane

The membrane already says contact and coupling require permission and that contamination must not spill across unrelated authority domains.

### Attributable Becoming

Freeport should preserve:

```
identity != participation != history != authority
```

while material remains foreign.

A thing may be exactly identified, deeply inspected, and richly witnessed without becoming locally authorized.

## Polyglot V2 pressure

A future polyglot system may use different native implementation languages for selected organs, but the security benefit is not language diversity by itself.

The useful pressure is that native runtime objects should not cross directly.

```
Organ A native state
      ↓
strict export adapter
      ↓
canonical inert crossing form
      ↓
FREEPORT
      ↓
strict import adapter
      ↓
Organ B native state
```

This can force several security boundaries to remain visible:

```
language boundary
+
process boundary
+
schema boundary
+
attribution boundary
+
authority boundary
```

A V2 organ should ideally survive replacement by a foreign implementation language without requiring neighboring organs to understand its internal runtime objects.

That becomes a test for hidden coupling:

> Can the rest of the system remain correct and secure without knowing which native language exists behind an organ's boundary?

## No universal translator brain

Do not solve polyglot translation with one central component that understands every organ's internals.

That would tend to become a hidden ontology, hidden authority surface, and eventually a hidden central brain.

Prefer:

```
Organ A
  ↕ A-owned adapter
portable inert contract
  ↕ B-owned adapter
Organ B
```

The middle should know as little as possible.

```
translator != authority
translator != ontology
translator != world model
```

## Capability posture

Inside Freeport, foreign material may be allowed to:

* preserve exact supplied bytes or a canonical inert representation;
* be hashed or content-addressed;
* preserve provenance and foreign claims as claims;
* be translated into additional **inert** projections;
* be inspected and compared;
* accumulate attributable witness receipts;
* remain unresolved;
* be refused;
* be re-exported without host adoption;
* petition a named local import gate.

It should not gain merely by residence:

* owner-runtime calls;
* destination-state mutation;
* ambient credentials;
* arbitrary network or filesystem access;
* arbitrary execution;
* local authority;
* automatic onward traversal;
* trust through age, frequency, recurrence, familiarity, or repeated inspection.

A useful summary is:

```
expression cheap
consequence expensive
```

## Unknown semantics

Unknown fields should not silently disappear, coerce, or become guessed meaning when the distinction could affect consequence.

```
UNKNOWN
  ↓
preserve as unknown where safely possible
  ↓
quarantine or refuse when consequential
  ↓
never silently invent semantics
```

This is especially important at polyglot boundaries, where two parsers or type systems may disagree about what the same bytes mean.

## Translation is not admission

A foreign artifact may successfully pass through several transformations:

```
protobuf
  ↓
canonical CBOR
  ↓
JSON projection
```

and still remain foreign.

Therefore:

```
translated != validated
validated != admitted
admitted != authorized
```

Successful understanding must not be confused with permission.

## Re-export without adoption

A hosted Freeport may allow:

```
World A
  ↓
Freeport hosted near World B
  ↓
World C
```

without implying:

```
World B adopted the artifact
```

So preserve:

```
hosted here != owned here
hosted here != believed here
hosted here != admitted here
re-exported here != constituted here
```

## Free-radical pressure analogy

The name collision is useful as a hostile metaphor.

In chemistry, a free radical is reactive because it contains an unpaired electron and can participate in propagation reactions.

The architectural analogy is not that foreign objects are chemically equivalent to radicals. It is narrower:

> **reactivity is not permission to propagate consequence.**

A foreign object may be highly capable of eliciting reactions from surrounding systems. Freeport exists to stop that reactivity from becoming an uncontrolled chain reaction across authority domains.

```
can react
!=
may alter local world
```

This gives the security model a useful question:

> What must be true before a reactive foreign thing may leave the capability vacuum and enter a consequential relation?

## MADDCL0WN residence

MADDCL0WN is a natural hostile resident specimen.

## Promotion gate

Do not make Freeport a universal runtime merely because the analogy fits.

Before promotion, require:

1. one deterministic hostile crossing specimen;
2. proof that unknown semantics fail closed or remain explicitly unresolved;
3. proof that translation cannot grant authority or execution capability;
4. proof of re-export without host adoption;
5. at least one polyglot boundary showing reduced accidental native-object coupling;
6. evidence that the topology adds security beyond ordinary process isolation and schema validation rather than merely renaming them.

Until then, Freeport is an incubating membrane pattern:

> **A foreign thing may arrive, remain visible, and be studied without thereby becoming part of the world that studies it.**
