# Continuity Witness — Shared Questions, Local Answers

**Status:** incubating architecture with multiple project-backed specimens

> **Continuity is an evidenced relationship across change, not a declaration of sameness.**

The eCODEsystem now has enough independent continuity-shaped work that the overlap is worth naming. The correct extraction is **not** a universal Continuity service. It is a small shared grammar for asking continuity questions while every project keeps its own answer, evidence, and authority law.

## The portable law

```
what is continuing?
from which exact ancestor/root(s)?
through what transformation?
under which environment / decoder / policy?
what was preserved?
what transformed?
what was lost?
what remains unresolved?
what residual evidence survives?
what authority, if any, crossed under separate evidence?
why is this projection current now?
```

A portable continuity witness may carry those answers across a boundary.

It does **not** carry execution authority across that boundary.

> **Witness ≠ warrant.**

Copying, serializing, transporting, retrieving, or re-rendering a continuity witness grants no capability, authorship, stewardship right, trust power, or execution permission.

## Shared questions, local answers

Two questions are becoming especially reusable:

### Why Current?

What attributable path explains why this form/projection is present now?

A good answer closes over exact roots, transformations, receipts, environment, and uncertainty. It does not substitute semantic similarity or narrative confidence for causal evidence.

### Still Alive?

Which declared invariants, obligations, tensions, residuals, relationships, or unresolved dimensions remain active in the current continuation?

A good answer may return plurality or uncertainty. It does not manufacture a clean resolution merely to tell a satisfying story.

These are portable questions—not one shared UI, daemon, graph, or database.

## Residual Topology

Most systems preserve successful transfer and discard the remainder. This architecture should preserve both sides.

A boundary may truthfully record:

* a property existed before and is absent after;
* an invariant weakened;
* a behavior no longer reproduces;
* a source root became unavailable;
* a branch was refused;
* a transformation is irreversible;
* a relationship remains unresolved;
* authority deliberately did not transfer.

That remainder is not garbage by default. It may be the most important evidence about how the system changed.

## Weather → Witness remains compatible

Continuity grammar does not promote observations automatically.

A useful maturation ladder remains:

```
weather
  ↓
influence
  ↓
candidate
  ↓
witness
  ↓
pattern
  ↓
adoption
```

Movement between stages requires local evidence/admission. A repeated idea does not become authority merely because it is familiar.

## Universal-benefit properties

If the pattern survives implementation, it supports five broad public-good properties:

1. **Portability without impersonation** — move state/memory/artifacts without falsely claiming identical embodiment.
2. **Succession without invisible capture** — stewardship can change while authority transfer remains explicit.
3. **Change without amnesia** — current state keeps an attributable return path.
4. **Failure without disappearance** — refusals, losses, unresolved branches, and dead ends remain usable evidence.
5. **Intelligence without automatic authority** — learned systems may observe, recommend, remember, and adapt without permission being inferred from capability.

## What must not happen

* no global Continuity service;
* no universal identity provider;
* no ecosystem-wide current-state database;
* no event bus required for continuity;
* no “same AI” ontology;
* no semantic similarity as root closure;
* no continuity witness that can execute a capability;
* no automatic stewardship/legal succession claim;
* no Project0 semantic validator deciding domain meaning;
* no forced convergence of project-specific schemas.

## Graduation gate

The architecture graduates only if:

1. Project0 Continuity Witness v0 becomes deterministic executable conformance;
2. TranchNode maps a real boundary specimen without weakening its stronger local loss semantics;
3. a materially different product (Corpus OS or jublEchat) maps its local witness without importing another project's execution laws;
4. the shared grammar catches at least one real false continuity / omitted-loss / authority-laundering case;
5. shared helper code is introduced only after those adapters prove repeated structure.

Until then, the correct topology is:

```
                    PROJECT 0
             portable grammar / tests
                       │
          ┌────────────┼────────────┐
          │            │            │
      TranchNode     Corpus OS    jublEchat
      boundary       WorldCut      read models
      residuals      succession    currentness
          │
      Haunted Toaster
      creative genealogy
```

The center is a **contract**, not a command center.

## Working compression

> **Shared questions. Local answers. Portable evidence. No portable authority.**

Project repos keep executable truth. GitBook keeps the constellation visible. Residual fog stays visible rather than being paved over.
