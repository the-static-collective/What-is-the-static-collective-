# Counterexample Origin & Typed Carrier — Failure Before Speciation

> **Status:** incubating cross-project architecture / executable questions, not shared runtime law
>
> **Date:** 2026-08-24

Two independently useful pressures have converged around the same mistake class:

1. a failed test can be mistaken for a failed law when the real failure is the abstraction or translation used to inspect it;
2. a continuity claim can be mistaken for persistence of the whole thing when only particular properties are actually carried forward.

The common discipline is:

> **Type the failure before changing the law. Type the conserved property before declaring continuity.**

## Why this appears now

The timing matters because several previously separate controls are now executable or materially sharper:

* National Treasure `SSW-MATH-001` proves that genuinely different graph worlds can share the same supplied observation and require an additional discriminator;
* Full Bowl 001 preserves a concrete failed world without rewriting it away;
* Full Bowl 002 reruns the unchanged hostile specimen against descendant repairs and proves that historical failure and present success may coexist;
* Free Graph Promotion/Invariance Crucible v0 has landed and can already derive clause-level `supports`, `only-one-domain`, `refuses`, and aggregate `split-required` without verdict ground truth;
* Death Is Local already requires an attributable carrier before local cessation can be promoted into a continuity story;
* Continuity Witness / Project0 already distinguish preserved, transformed, lost, broken, unresolved, reconstituted, and authority-separated continuity.

The missing work is therefore not a new universal doctrine. It is two small type systems around existing machinery.

***

## I. Counterexample Origin

A hostile specimen should not be permitted to pressure a candidate portable law until the system asks what kind of counterexample occurred.

Candidate classification:

```
COUNTEREXAMPLE_ORIGIN
  = abstraction
  | concrete
  | unresolved
  | poison
```

### `abstraction`

The apparent violation cannot be reproduced under the concrete owner-local semantics. The observation, projection, adapter, or translation was too coarse or otherwise misleading.

Disposition pressure:

```
REFINE-TRANSLATION
REFINE-DISCRIMINATOR
PRESERVE-CANDIDATE-PROVISIONALLY
```

This is the eCODE-relevant extraction from counterexample-guided abstraction refinement: a spurious counterexample pressures the abstraction, not automatically the property.

### `concrete`

The violation reproduces against the owning system's actual semantics with sufficient attributable evidence.

Only here may the candidate law itself be pressured toward:

```
REFUSE
NARROW
SPLIT
SUCCESSION
LOCAL-DEATH
```

### `unresolved`

There is not enough owner-local evidence to determine whether the failure belongs to the abstraction or the concrete behavior.

This outcome is load-bearing. The crucible must be allowed to refuse forced certainty.

```
insufficient witness
!=
translation failure
!=
genuine counterexample
```

### `poison`

The specimen or adapter tries to manufacture a desired disposition through copied vocabulary, renamed verdict categories, false declarations, or other integrity attacks.

Poison is not positive portability evidence and should not be counted as an independent embodiment of any law.

## Why this belongs before speciation

Promotion speciation currently asks what to do when a candidate survives some domains and fails another.

The new ordering should be:

```
candidate P
  ↓
hostile domain C
  ↓
apparent failure
  ↓
COUNTEREXAMPLE_ORIGIN?
  ├─ abstraction → refine translation/discriminator
  ├─ unresolved  → seek owner-local witness
  ├─ poison      → refuse integrity attack
  └─ concrete    → pressure P itself
                    ↓
                 REFUSE | NARROW | SPLIT | SUCCESSION | LOCAL-DEATH
```

This prevents two symmetric laundering moves:

```
every failed translation → "the law is false"

every genuine violation  → "the translation was imperfect"
```

Both destroy evidence.

## Founding control triad

### SSW-MATH-001

Two non-isomorphic worlds share the supplied observation. Re-expression cannot recover missing information. A new discriminator can.

**Control:** refine the observation surface.

### Full Bowl 001

The hostile crossing exposed concrete integration leaks under then-current owner semantics.

**Control:** repair the world while preserving the failed witness.

### Full Bowl 002

The same hostile specimen passes against descendant repairs while the prior failure remains historical fact.

**Control:** success in a descendant world does not erase the ancestor's failure.

## II. Typed Carrier / Conservation Witness

Death Is Local already supplies the first carrier obligation:

```
CONTINUITY_AFTER_LOCAL_CESSATION(X)
requires
CARRIER(X) + ATTRIBUTION(X) + BOUNDARY + EVIDENCE
```

The next refinement is property typing.

A carrier need not carry all of `X`.

Candidate relation:

```
CARRIER(c, X, property, boundary, evidence)
```

Possible carried properties include:

```
lineage
bytes
causal consequence
reconstructive state
relationship evidence
constraints / obligations
addressable loss
navigable relation
```

Possible explicitly non-carried properties include:

```
present authority
original occurrence
material identity
current participation
full reconstructive state
```

Therefore these can all be simultaneously true:

```
presence-continuity(X)  = false
lineage-continuity(X)   = true
consequence-continuity  = true
authority-continuity(X) = false
```

That is not contradiction. It is a more exact statement of what survived.

## Carrier is not identity

Examples:

* a Git commit may carry ancestry without carrying current execution authority;
* a tombstone may carry deletion history without carrying the deleted object's state;
* a manuscript copy may carry text without carrying one unique historical embodiment;
* a refusal receipt may carry causal consequence without carrying admission;
* a reconstructed world may carry navigable relation without impersonating the original occurrence.

The governing question is therefore two-part:

> **Where is it carried?**
>
> **What, exactly, does that carrier preserve?**

## Death Is Local applies cautiously to laws

A useful unsliced analogy is:

```
FAILS_IN(P, domain_C, evidence)
!=
EXTINCT_EVERYWHERE(P)
```

A portable candidate may fail in one domain while remaining historically supported elsewhere. A narrower descendant may later succeed without rewriting the parent's earlier failure.

This is not yet a shared law. The important executable question is whether the new candidate is genuinely descended from the parent or merely post-hoc renaming after failure.

Speciation must therefore preserve attributable ancestry.

## Smallest executable ladder

### 1. COUNTEREXAMPLE-ORIGIN-001

Manufacture four cases around one candidate invariant:

A. same concrete behavior, coarse/bad translation → `abstraction`

B. correct translation, owner semantics genuinely violate invariant → `concrete`

C. insufficient owner-local witness → `unresolved`

D. MADDCL0WN renames categories / copies expected vocabulary → `poison`

Required result: four different dispositions without importing domain authority into the crucible.

### 2. Project0 CARRIER-001

Use the existing Typed Continuity Braid as the native owner.

Three hostile cases:

A. local process disappears; another attributable carrier preserves exact reconstructive state;

B. only a receipt survives; consequence/lineage continuity may remain, but state continuity does not;

C. resemblance survives with no attributable descent; continuity is refused.

The output should name the carried property, boundary, evidence, and explicitly ended authority.

### 3. SSW-CARRIER-001

National Treasure supplies two worlds with the same visible present observation:

```
present(X) = 0
```

but different carrier histories.

Ask for the cheapest additional witness distinguishing:

```
globally extinct
```

from:

```
locally absent + attributable continuation
```

National Treasure tests identifiability. It does not become the owner of continuity semantics.

### 4. Free Graph harvest

Only after independent owner-local specimens exist should Free Graph ask what survived translation.

Do not manufacture the second embodiment inside the promotion crucible merely to make the clause green.

## Neighboring application: THE FAMILIAR

The new Familiar hypothesis makes typed carriers immediately relevant.

If relationship-shaped behavior survives engine death or migration without one persistent sovereign machine-self, then a future FAMILIAR specimen must answer:

```
what is the relationship carrier?
what property does it preserve?
is the receipt itself the carrier?
is it evidence pointing to a carrier?
is it sufficient material for lawful reconstruction?
what authority explicitly did not survive?
```

Those are mechanically different claims.

A vague "the relationship continued" is insufficient.

***

## Non-promotion boundary

Do not promote from this slice alone:

* CEGAR as a universal eCODE law;
* `DEATH` as a universal primitive;
* a shared Carrier runtime or schema;
* new Free Graph relation verbs;
* a Boolean `continues(X)` primitive;
* residue as proof of identity;
* continuity as revived authority;
* domain-local failure as global extinction.

## Working compression

> **Did the thing fail, did the view fail, or is the witness incomplete?**
>
> **If continuity is claimed: what survived, where is it carried, and under which boundary?**
