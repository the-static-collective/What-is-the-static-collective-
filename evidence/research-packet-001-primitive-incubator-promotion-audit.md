# Research Packet 001 — Primitive Incubator Promotion Audit

**Observed:** 2026-08-28/29\
**Authority boundary:** this packet classifies and routes research. It does not supersede repository-owned code, exact commits, project-native evidence, or the historical incubator leaves from which it was derived.

> **Promotion is extraction, not erasure.**

The Primitive Incubator has succeeded well enough to create a new problem: it is no longer one maturity class. It now contains raw seeds, coherent hypotheses, landed project specimens, cross-project laws, active implementation proofs, metaphor portals, and nested research programs in one navigation surface.

The correct response is not to delete the cortex. It is to give the cortex lobes.

## Diagnosis

The Incubator was designed for ideas that were worth preserving before they became roadmap obligations. Its own graduation rule asks whether a reusable primitive has survived enough pressure to deserve another home.

That rule has already worked. Stigmergic Field and Ghost / Residual Presence graduated while their origin records remained historically visible.

The present failure mode is therefore not bad research. It is **successful research without enough disposition**.

Several current leaves explicitly say things such as:

* first executable specimen landed;
* project-backed hypothesis retained;
* dedicated repository exists;
* implementation green, live specimen pending;
* cross-project candidate law;
* still exploratory / metaphor portal.

Those statements describe materially different states. Keeping all of them as equal siblings under `Primitive Incubator` makes navigation lie about maturity.

## Promotion ladder

Use two independent questions:

1. **How much has this idea been tested?**
2. **What kind of permanent home, if any, has it earned?**

A useful research-state ladder is:

```
SEED
  observation or felt possibility

ACTIVE RESEARCH
  coherent hypothesis + invariants + falsifiable smallest experiment

PROJECT-BACKED
  at least one owner-local executable or witnessed specimen has landed

CROSS-PROJECT
  materially different domains reproduce the useful invariant
  without importing one owner's local schema

PROMOTE
  extract the durable result into Pattern / Evidence / Vocabulary / Project State / project-owned docs

HOLD | SPLIT | RETIRE
  unresolved, overbroad, aesthetic-only, superseded, or disproven
```

**PROJECT-BACKED is not the same as PATTERN.** One landed implementation earns Evidence. A portable law normally requires materially different embodiments.

## Navigation law

The Incubator should stop making every raw leaf a first-class hallway door.

Preferred topology:

```
Front Room
   ↓
Incubator
   ↓
6–8 research packets
   ↓
bounded child leaves / source ancestry
```

A reader should be able to understand **what kind of question is alive** before loading every experiment that ever touched it.

Raw notes remain addressable and linkable. Packetization changes navigation, not history.

## Promotion rule for project-backed leaves

A simple maintenance rule catches much current drift:

```
IF a leaf says
  "first specimen landed"
  OR "project-backed"
  OR names a dedicated canonical project/repo
THEN
  the Primitive Incubator is probably no longer its active home.
```

Disposition should then be one of:

```
project-owned docs
Evidence witness
Project State
Pattern review
still-active research packet
```

The historical origin leaf may remain, but it should carry a visible disposition pointer rather than pretending the experiment is still unborn.

## Promotion receipt

Every future graduation should leave a tiny receipt:

```
origin:
what survived:
what failed or was discarded:
materially different specimens:
new home:
canonical authority:
residual fog:
```

That is enough to make promotion attributable without turning GitBook into a governance engine.

## What not to do

Do not solve the size problem by:

* deleting strange ideas;
* flattening them into one ontology;
* declaring every recurring phrase a Pattern;
* making GitBook canonical over project repositories;
* creating a shared package merely because several pages use similar words;
* moving a page and losing its original research ancestry;
* treating one executable specimen as universal validation;
* letting popularity, repetition, or aesthetic resonance manufacture authority.

```

    ↓
research packet
    ↓

    ↓

  ↙   ↓    ↘
```

> **The Incubator should be a greenhouse, not a warehouse.**

The greenhouse may contain thousands of seeds. The doorway only needs to show which beds are alive, which plants have been transplanted, and which experiments are still waiting for weather.
