# Full Bowl 001 × MADDCL0WN — design

## Status

Executed bounded specimen. Ten live checks pass. Two witness-surface leaks are recorded. Repairs are deferred to owner issues.

## Goal

Prove or falsify one end-to-end path of attributable becoming:

```text
thing → encounter → admission → authority → attempt → outcome
      → causal accounting → WorldCut → continuity → return → reachability
```

The proof must preserve every adjacent boundary while MADDCL0WN supplies contradictory, causally impossible, authority-looking, lineage-breaking, and ontologically incompatible material.

## Constraints

* one synthetic specimen;
* exact owner-head Task World Cut;
* explicit lawful/refused/unresolved expectation at every crossing;
* existing owner process adapters and modules wherever available;
* fixture-backed projection called a projection;
* leak ledger instead of automatic repair;
* at most three repair issues, only after live exposure;
* no universal schema, shared runtime, portable authority, or DDD.

## Chosen architecture

The integration repository owns one fixture, one validator, one CLI, and one optional live probe.

Project0 continues to own encounter identity and purpose-relative continuity. Corpus OS continues to own admission, adopted authority, Session execution, causal accounting, WorldCut, continuity attestation, and latent reachability. TranchNode continues to own the continuity boundary witness.

The integration runner compares outputs and records gaps. It never re-exports an owner authority object.

## Alternatives

### Corpus-owned orchestration

This would expose local phase objects more easily, but it would make Corpus responsible for Project0 and TranchNode meanings. Rejected.

### Central Full Bowl runtime

This would offer one apparent API while merging or shadowing donor contracts. Prohibited by the task.

### Documentation-only witness

This would preserve a story but not test silent promotion. Rejected because executable owner surfaces exist.

## Falsifiers

The fixture check fails if:

* any of the ten crossings is removed, reordered, or collapsed;
* any crossing lacks a lawful, refused, or unresolved expectation;
* any hostile item promotes itself;
* source authority travels in the Project0 envelope;
* visible return erases the changed history ref;
* the lookalike shares the allowed material root;
* automatic repair is enabled;
* more than three repair issues are proposed.

The live probe exits nonzero if the lawful address/verify/admit path fails, the forged authority is not refused, missing subject is not indeterminate, WorldCut or continuity classes collapse, the lookalike conforms, or the copied warrant becomes reachable.

## Evidence modes

The live report labels each crossing as process-adapter evidence, owner-module projection, owner-test evidence, or unresolved boundary coverage. Those modes cannot be rewritten into one generic “verified” claim.

## Leak policy

A leak must be produced by a live owner surface at the pinned head. Fixture expectations alone cannot create a leak.

An exposed leak receives:

* stable ledger id;
* exact crossing;
* observed owner output;
* authority-expansion assessment;
* one smallest repair candidate.

The Full Bowl branch does not apply the repair.
