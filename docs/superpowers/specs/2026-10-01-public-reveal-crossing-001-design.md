# PUBLIC REVEAL CROSSING 001 — Relay Garden Design

Date: 2026-10-01  
Status: written-spec review  
Scope: public first-contact experience + generative participation loop  
Canonical design home: `the-static-collective/What-is-the-static-collective-`

> **EVERYONE GETS A DOOR.**
>
> **EVERYTHING MADE MAKES ANOTHER DOOR.**

## 1. Purpose

The Static Collective is approaching a public reveal with more public material than any first-time visitor should be expected to understand at once.

The reveal therefore must not behave like a catalog launch, repository dump, manifesto wall, or compressed explanation of the entire Collective.

It should prove one thing by letting a stranger participate:

> **This is a traversable creative world in which attributable action can create new possibility without silently creating new authority.**

PUBLIC REVEAL CROSSING 001 is the first bounded public encounter built around that promise.

A visitor arrives, receives at least one makeable door, explicitly chooses whether to cross it, makes one bounded thing, receives a receipt, and sees a small set of new possible doors that exist because that thing was made.

The reveal succeeds when the visitor understands the grammar because they caused it, not because they read a theory of it.

## 2. Governing promise

The public promise is:

```text
ARRIVE
  -> RECEIVE A MAKEABLE DOOR
  -> SELECT
  -> CROSS
  -> MAKE ONE THING
  -> RECEIPT
  -> FRUIT / SEED / COMPOST
  -> NEW POSSIBLE DOORS
```

The constitutional compression is:

```text
DOOR != CROSSING
SEED != SELECTION
CREATION != AUTHORITY
MAKE != PUBLISH
PUBLISH != CANON
INFLUENCE != OWNERSHIP
FAILURE != NOTHING

CREATION -> NEW POSSIBILITY
```

The experiential seal is:

> **EVERYTHING MADE LEAVES THE WORLD WITH MORE POSSIBILITY THAN IT FOUND.**

This is a possibility guarantee, not a publication guarantee and not an execution guarantee.

A completed make may remain local, private, refused, held, unpublished, or non-canonical and still lawfully open another chance.

## 3. Selected architecture — Relay Garden

Three public shapes were considered.

### A. Infinite feed

Every artifact enters a chronological stream and exposes follow-up actions.

Rejected as the primary shape because chronology would flatten topology and reproduce ordinary social-media gravity.

### B. Infinite rooms

Every artifact immediately becomes a full inhabitable room with multiple projections and doors.

Deferred as the deeper shape because it is powerful but too heavy for first contact.

### C. Relay Garden

Selected.

The first public surface is a **Relay Garden**: a thin experience layer where each completed make can yield a bounded Chance Set.

A Chance Set contains a small number of proposed next doors. Those doors may later open into richer ROroomOM-style rooms, but the first encounter remains intentionally small.

```text
artifact
  |
  +-> fruit: what actually changed
  +-> seed: one or more possible next doors
  +-> compost: failure, uncertainty, rejected assumptions, dead paths
  |
  +-> chance set
         |
         +-> human may select one
         +-> human may invent another
         +-> human may leave
```

The garden grows by proposal. It does not execute descendants automatically.

## 4. Placement and ownership

PUBLIC REVEAL CROSSING 001 is a cross-project composition contract, not a new source of truth for donor projects.

### Canonical design ownership

This design belongs in `What-is-the-static-collective-` because that repository already owns the public Front Room, project orientation, cross-project maps, patterns, and public explanatory boundaries.

### Runtime placement

The first executable host should be the planned **ORCHARD** experience organ, with **Relay Garden 001** as its first public mode.

If no ORCHARD runtime repository exists when implementation begins, the implementation plan should create one rather than putting runtime behavior into the Front Room repository.

The Front Room remains a threshold and stable landmark. It may link into Relay Garden. It must not become the runtime.

### Donor authority

Relay Garden composes donor contracts while leaving authority with their owning projects.

It does not become:

- reLATTE;
- BananaSpork;
- 12:01;
- Banana Relay;
- ROroomOM;
- Full Measure;
- WITNESS;
- Haunted Toaster;
- ALEX;
- any artifact owner;
- any publication or canon authority.

Core boundary:

> **THE GARDEN MAY OPEN DOORS BETWEEN ORGANS. IT MAY NOT BECOME THEIR SOVEREIGN.**

## 5. Donor contracts

### reLATTE — relation substrate

reLATTE supplies the core relational interpretation:

> **The relation is the block.**

A public creation is not valuable because it increments a global counter. It is valuable because it creates an attributable relation between a source, a participant, a consequence, and one or more possible continuations.

Relay Garden should preserve addressed relations rather than invent a global-state or token model.

Relevant current donor material:

- `reLATTE/docs/COM5-CAPSULE-001.md`
- reLATTE identity/signature and crossing work

### 12:01 Door — human crossing gate

BananaSpork's 12:01 specimen supplies the transition discipline:

```text
RECOMMENDATION != SELECTION
DOOR != CROSSING
CROSSING != ACT
ACT != RECEIPT
```

Relay Garden may recommend doors, but recommendation cannot itself cross them.

The first slice must preserve explicit human selection before an effectful crossing.

### Banana Relay — succession law

Banana Relay supplies the post-act decomposition:

```text
FRUIT   = what actually changed
SEED    = a possible next door
COMPOST = failure, uncertainty, rejected assumptions, dead paths
```

Its existing law remains intact:

> **AN ELF MAY LEAVE A DOOR. IT MAY NOT OPEN IT FOR ITS SUCCESSOR.**

Relay Garden generalizes the human-facing projection of that law. A completed public make can expose seeds without granting those seeds selection or crossing authority.

### ROroomOM — deeper inhabitation

ROroomOM supplies the deeper projection pattern.

A created particular may later be entered through multiple doors such as:

```text
ARTIFACT / ROOM
  -> HEAR
  -> READ
  -> WATCH
  -> PLAY
  -> REMIX
  -> CONTINUE
```

Different projections must not silently become different source truths.

Relay Garden does not need full room inhabitation in v0. It only needs to preserve enough addressability that a future door can enter a richer room without losing ancestry.

### ORCHARD / PICKER — human experience layer

The existing ORCHARD + PICKER design supplies the experience principle:

- anatomy hidden by default;
- provenance one gesture away;
- few first-screen choices;
- useful refusals;
- same core, different hands;
- delight without erasure.

Relay Garden is the first public, generative ORCHARD mode.

### Full Measure — participation without worth scoring

Participation may create more relation, more history, and more possible crossings.

It must not imply more human worth, more intrinsic status, or automatic governance authority.

```text
participation -> more relation
participation -> more history
participation -> more possible crossings

participation != more human worth
participation != governance supremacy
participation != algorithmic privilege
```

## 6. Public encounter

The desired stranger path is:

```text
"What is this?"
    ->
"I understand one thing."
    ->
"Wait, I can do something?"
    ->
MAKE
    ->
"That actually changed something."
    ->
"Those doors did not exist before."
```

The public reveal should not require prior knowledge of:

- repository anatomy;
- Collective vocabulary;
- COM5;
- reLATTE;
- authority contracts;
- branch topology;
- project history.

The machinery becomes inspectable after the encounter, not a prerequisite to it.

## 7. First-chance rule

Every arrival should receive at least one genuine chance to make something.

This is not a promise that every visitor can perform every action.

A starter chance must be selected from a bounded set whose prerequisites are currently satisfiable.

Examples:

- hear a song fragment and make an image;
- read a paragraph and leave one sentence;
- record one Scripture verse where the owning WITNESS flow permits it;
- remix an attributed fragment;
- test a machine and leave a reproducible observation;
- continue an unfinished story seed;
- draw something from a song;
- repair a confusing doorway;
- classify or clarify an unresolved artifact without deciding its truth.

At least one starter path should avoid requiring reputation, prior contribution history, or deep Collective knowledge.

Where practical, at least one starter path should also avoid requiring an account before the visitor can make something locally.

Accountless making does not imply accountless publication.

## 8. MAKE is not PUBLISH

This distinction is mandatory.

```text
MAKE
  -> local consequence exists
  -> receipt can exist
  -> new possibility can exist

PUBLISH
  -> separate owner/admission decision

CANON
  -> separate owner-local authority decision
```

A completed make can therefore have dispositions such as:

- local only;
- private;
- held for review;
- refused for publication;
- admitted to a public project surface;
- later superseded;
- public but explicitly non-canonical.

Relay Garden must never rewrite refusal or privacy as nonexistence.

The possibility engine may derive a next door from:

- the artifact itself;
- its process;
- its compost;
- an unresolved question;
- a failed attempt;
- a missing capability;
- a request for repair;
- a safe local continuation.

This is how the system preserves the law that everything made opens another chance without forcing every artifact into public circulation.

## 9. Minimal public records

Relay Garden should avoid becoming a second ontology. Its records are projections that point back to owner-local facts.

### `relay-garden.door/v0`

A proposed public chance.

Minimum fields:

```text
door_id
label
kind
source_refs[]
owner
requirements[]
write_horizon?
visibility
selection_authority = human
crossing_authority = false
created_at
```

A door may be displayed before selection. It may not cross itself.

### `relay-garden.make-receipt/v0`

A projection that records one completed bounded make.

Minimum fields:

```text
receipt_id
door_ref
participant_ref?
anonymous_local = true|false
source_refs[]
owner_receipt_refs[]
artifact_refs[]
fruit[]
compost[]
visibility
publication_disposition
created_at
```

If an owning organ already has a stronger receipt, Relay Garden references it rather than replacing it.

### `relay-garden.chance-set/v0`

A bounded proposal set derived after a make.

Minimum fields:

```text
chance_set_id
parent_receipt_ref
proposed_doors[]
derivation_refs[]
max_visible
created_at

selection_authority = human
crossing_authority = false
```

The first slice should default to no more than three visible generated doors from one make.

A human-authored additional door may coexist with those proposals.

## 10. Chance generation

A completed make must be able to produce at least one next chance.

The system should prefer the smallest lawful continuation that preserves ancestry.

Candidate classes include:

- **continue** — extend the same artifact or sequence;
- **remix** — transform while preserving source references;
- **translate** — carry into another medium or representation;
- **repair** — address a failure, ambiguity, or broken doorway;
- **witness** — inspect, test, annotate, or verify;
- **embody** — move from representation toward performance or material action where an owner permits it;
- **branch** — pursue a different unresolved possibility;
- **return** — carry a consequence back toward a source or participant;
- **compost** — investigate a failure or rejected path.

Chance generation is proposal generation.

It may use deterministic rules, owner-provided adapters, human suggestions, or AI assistance, but every proposal must preserve:

- source references;
- owner;
- why the door was proposed;
- required capability or admission conditions;
- no implicit execution authority.

## 11. Anti-explosion rule

The recursive system is intentionally generative, so it requires a strict governor.

> **Every completed make must be able to expose another chance. No make may automatically execute its descendants.**

The v0 limits are:

- maximum three machine-proposed visible doors per completed make;
- zero automatic descendant crossings;
- zero automatic publication;
- zero automatic canon promotion;
- zero inherited participant authority;
- zero reputation multiplier for prolific making.

A door may remain unopened indefinitely.

No activity debt is created by an unopened door.

## 12. Freshness and public truth

The reveal must be backed by current project evidence.

The Front Room may orient toward a project, but project-owned repositories, landed code, tests, current receipts, and current project documentation outrank reveal copy.

Before an owner-backed starter door is enabled publicly, Relay Garden must know whether its required action is:

- executable and current;
- proposal-only;
- local-demo only;
- blocked;
- stale;
- unavailable.

A stale or proposal-only door may still be shown if clearly labeled, but it may not masquerade as executable.

The public reveal should carry a dated snapshot witness of the current opening state without claiming the Collective has stopped changing.

## 13. Failure and refusal behavior

Refusal is a first-class outcome.

Examples:

- source disappeared;
- owner adapter is stale;
- publication not allowed;
- required capability unavailable;
- participant withdraws;
- output fails validation;
- no safe public next door can be derived;
- downstream owner refuses admission.

A refusal must preserve the attempted relation where appropriate and should yield either:

1. a local-only next chance;
2. a repair/witness chance;
3. compost explaining why no continuation was proposed.

The system must never fabricate success merely to maintain momentum.

## 14. Public surface

The first public page should remain small.

A suggested shape:

```text
[ one sentence: what this place is ]

MAKE SOMETHING
  [ door ]
  [ door ]
  [ door ]

[ small "show me something real" specimen ]

after make:
  WHAT CHANGED
  YOUR RECEIPT
  WHAT CAN EXIST NOW
    [ next door ]
    [ next door ]
    [ next door ]

[ trace this ]
[ leave ]
```

The first screen should not expose the whole graph.

The visitor should always be able to leave without punishment, streak loss, unfinished-task pressure, or manipulative notification debt.

## 15. Proof, not pitch

Every major public claim should resolve to something inspectable.

Preferred proof forms include:

- repository;
- executable specimen;
- test;
- render;
- song;
- book;
- source packet;
- receipt;
- commit;
- current owner-local status.

The reveal should survive a skeptical stranger clicking randomly.

Where evidence is partial, the surface should say so.

## 16. First executable slice

The first implementation should prove the generative loop with the fewest moving parts possible.

### In scope

- new ORCHARD runtime repository if no ORCHARD runtime exists at implementation start;
- Relay Garden 001 public mode;
- three to five curated starter doors;
- at least one starter door that can produce a local artifact without prior reputation;
- explicit door selection;
- explicit crossing for effectful actions;
- one bounded make;
- a receipt that references owner/source material;
- fruit / seed / compost projection;
- a bounded Chance Set with at most three machine-proposed doors;
- no automatic descendant crossing;
- local/private disposition;
- held/refused/publication disposition;
- provenance reveal one gesture away;
- one specimen showing failure or refusal still yielding useful compost or a repair door;
- one specimen showing the same created artifact with more than one lawful projection/continuation;
- deterministic fixture coverage for the core state machine.

### Deferred from the first slice

- universal graph search;
- personalized ranking;
- social follower graph;
- engagement optimization;
- token economy;
- reputation economy;
- global consensus;
- automatic publication;
- automatic canon;
- autonomous multi-generation execution;
- unrestricted cross-repository writes;
- full ROroomOM inhabitation;
- every Collective project as a live adapter;
- persistent notifications;
- gamified streaks;
- governance derived from contribution volume.

## 17. First starter-door set

The implementation plan should choose three to five doors from owner surfaces that are current enough to prove the loop.

The preferred mix is:

1. **creative transformation** — e.g. song -> image / short text / visual continuation;
2. **witness / repair** — test something, notice something, improve a doorway;
3. **narrative continuation** — continue one bounded story seed;
4. **community contribution** — only where the owning flow is currently safe and explicit;
5. **failure/compost** — a door whose useful outcome may be evidence rather than polished artifact.

The set should demonstrate heterogeneity without requiring five different backend systems.

## 18. Acceptance criteria

PUBLIC REVEAL CROSSING 001 is implemented only when all of the following are demonstrably true.

### First contact

- A visitor can reach Relay Garden from the public Front Room without learning repository anatomy first.
- The first surface shows no more than five starter doors.
- At least one starter door is usable without prior contribution history or reputation.

### Crossing discipline

- A displayed door cannot execute itself.
- Selection is recorded separately from crossing.
- Effectful crossing requires an explicit human action.
- A recommendation or generated Chance Set cannot inherit execution authority.

### Making

- One starter door can produce a real bounded artifact or attributable observation.
- The completed make yields a receipt.
- The receipt references source/owner material rather than replacing owner truth.
- A failed or refused make remains distinguishable from a successful one.

### New possibility

- Every completed make in the v0 fixture set can expose at least one next chance.
- A next chance may be local/private when publication is refused.
- Machine-generated Chance Sets expose at most three visible proposals.
- No proposed next door executes automatically.

### Publication boundary

- MAKE and PUBLISH are separate operations or dispositions.
- Publication refusal does not erase the make.
- Public visibility does not imply canon.
- Owner-local admission remains owner-local.

### Provenance

- A visitor can reveal why a door or artifact is present in one gesture.
- Source references remain inspectable.
- Missing or stale provenance remains visibly missing or stale.

### Human-value boundary

- Contribution count does not increase crossing authority.
- Contribution count does not determine visible human worth or rank.
- No streak, scarcity timer, or engagement-pressure mechanic is required for continuation.

### Verification

- Deterministic tests cover proposal -> selection -> crossing -> make -> receipt -> Chance Set.
- Tests cover refusal/private disposition.
- Tests cover no automatic descendant execution.
- Tests cover duplicate/replay behavior for the chosen local record format.
- A manual stranger-path smoke test can be run from Front Room -> make -> next door.
- Public copy is checked against current owner-project status before launch.

## 19. Stranger-path review

Before public opening, run at least one adversarial first-contact walkthrough from the perspective of a person who suspects the project may be:

- AI sludge;
- vaporware;
- an inside joke;
- an incomprehensible GitHub dump;
- a collection of unrelated experiments;
- a system that quietly overstates what is executable.

The walkthrough should record confusion points and evidence failures.

Only repair places where the interface or evidence fails to carry the truth.

Do not remove strangeness merely because it is strange.

## 20. Non-goals

PUBLIC REVEAL CROSSING 001 is not:

- a master application;
- a new global ledger;
- a replacement for reLATTE;
- a replacement for owner-local receipts;
- a social network;
- a content popularity engine;
- a creator reputation system;
- a token system;
- a universal AI agent;
- a requirement that every artifact become public;
- a claim that every Collective project is production-ready;
- an attempt to explain the entire Collective on one page.

## 21. Failure conditions

The reveal is failing if:

- the visitor must understand the architecture before making something;
- making something silently publishes it;
- a generated seed executes itself;
- prolific users gain hidden authority;
- refusal is rewritten as failure or disappearance;
- the Front Room becomes an application shell;
- Relay Garden becomes source authority for donor projects;
- provenance disappears behind a pleasant interface;
- new chances are optimized for engagement instead of lawful continuation;
- every make produces so many options that none matter;
- unresolved material is completed for narrative neatness;
- private or refused artifacts are forced into public circulation;
- the public surface claims current capabilities that owner projects do not support.

If this happens, make the garden smaller.

## 22. Implementation handoff boundary

This document approves architecture only.

After written-spec review:

1. create the implementation plan using the normal Superpowers planning workflow;
2. confirm the runtime repository and first three-to-five starter doors against current evidence;
3. decompose implementation into bounded tasks;
4. use Develoop to preserve the accepted plan as implementation-ready GitHub work rather than reconstructing it from chat;
5. use Riqor evidence gates during implementation so completion claims follow fresh repository verification;
6. preserve canonical design and decision state according to Knowledge Steward rules.

No runtime repository, implementation issue, code, deployment, or public launch should be created from conversational approval alone.

## 23. Compression

```text
THE FRONT ROOM SAYS: YOU ARE HERE.

RELAY GARDEN SAYS: YOU CAN DO SOMETHING.

12:01 SAYS: A DOOR DOES NOT CROSS ITSELF.

BANANA RELAY SAYS: AN ACT MAY LEAVE FRUIT, SEED, AND COMPOST.

reLATTE SAYS: THE RELATION CAN BE ADDRESSED WITHOUT BECOMING GLOBAL SOVEREIGNTY.

ROroomOM SAYS: THE SAME PARTICULAR MAY BE INHABITED THROUGH DIFFERENT DOORS.

```

The reveal therefore says:

> **WE MADE THIS. NOW YOU GET TO MAKE SOMETHING.**
>
> **THAT CHANGED THE WORLD A LITTLE.**
>
> **HERE ARE THE DOORS THAT EXIST NOW THAT DID NOT EXIST BEFORE.**
